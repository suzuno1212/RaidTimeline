タイムラインとプラン

2 つのファイルの考え方と書き方です。どちらも Lua の表の形ですが、アドオンは Lua として実行せず、表として読むだけです。

考え方

タイムライン（みんなで共通）

「このコンテンツでは、いつ・どの敵が・何の技を使うか」。アクションのことは書きません。
timelines\<mapid>_<名前>.lua

プラン（自分用）

「どの技の・何秒前に・何を使うか（何を鳴らすか）」。ジョブ・ポジションごと。
plans\<mapid>\<ジョブ>_<ポジション>.lua

プランは秒数ではなく タイムラインのイベント を基準に書きます。だから、タイムラインを正確なものに差し替えても、プランはそのまま使えます（イベントの ID が変わったときは、変換ツールで 付け替え られます）。

フェーズと時計

  • フェーズは「順番」ではなく きっかけ（トリガー） で入ります。並びに意味はないので、プルで順番が入れ替わる戦闘でも、来たきっかけのフェーズに入ります。
  • 同じフェーズには 1 プルで 1 回だけ入ります。
  • フェーズに入ると時計が 0 から進みます。詠唱を照合するたびに、予定の時刻を実際の時刻で上書きします。
  • 同期点（syncs）が来ると、時計をその秒数に合わせ直します（ずれが window 秒より大きいときは合わせません）。
  • 秒数の基準は、パーティが最初に敵を攻撃した時刻です。

タイムラインの書き方

return {
    format = 1,
    meta = {
        name = "サンプル", mapid = 9001, version = 1, author = "suzu",
    },
    actions = {                      -- 技名（表示だけに使う。照合は ID）
        [40001] = "全体攻撃",
        [40002] = "技A", [40003] = "技B",
    },
    entities = {                     -- 敵の登録
        boss = { name = "サンプルボス", contentid = 9001 },
    },
    phases = {
        {
            id = "p1", name = "前半",
            trigger = { type = "combat_start" },
            events = {
                -- t = フェーズ開始から詠唱開始まで、cast = 詠唱時間（着弾は t + cast）
                { id = "p1_raidwide", name = "全体攻撃", t = 10.0, cast = 5.0,
                  match = { entity = "boss", action = 40001 } },
                -- A か B のどちらかが来る（分岐・ランダム）
                { id = "p1_ab", name = "技A / 技B", t = 25.0, cast = 6.0,
                  match = { entity = "boss", action = { 40002, 40003 } } },
            },
            syncs = {
                { on = { type = "cast_start", entity = "boss", action = 40001, nth = 1 }, t = 10.0, window = 10.0 },
            },
        },
    },
}

フェーズのきっかけ（trigger）

type項目意味
combat_start戦闘開始
cast_startentity・action・nthその敵がその技の詠唱を始めた（nth：戦闘開始から何回目か）
hp_belowentity・percentHP が〇% 以下になった
targetableentity・state・nthターゲットできる（true）/ できなくなった（false）

イベントの項目は id（プランから指す。全体で重ならない）・name・t・cast・match・tolerance（照合を受け付ける時刻のずれ。既定 5 秒）です。

プランの書き方

ふつうは プラン編集 の画面で作れば十分です。手で書くときはこの形です。

return {
    format = 1,
    meta = { mapid = 9001, timeline = "9001_sample", timelineVersion = 1, job = "PLD", position = "MT" },
    entries = {
        {   -- 全体攻撃の着弾 3 秒前に、防御スキル A を自分に
            id = "guard1", event = "p1_raidwide", ref = "hit", offset = -3.0, window = 3.0,
            action = { id = 1001, type = 1 }, target = { type = "self" },
            sound = "raidwide.wav",
        },
        {   -- 技 A のときだけ鳴らす（技 B なら「対象外」）
            id = "ab_snd", event = "p1_ab", ref = "start", offset = 0.0,
            onAction = 40002, sound = "left.wav",
        },
    },
}
項目既定説明
eventタイムラインのイベント ID
ref"hit"基準。"start"（詠唱開始）か "hit"（着弾）
offset0基準からの秒数（マイナスで前）
window3.0リキャスト中なら、この秒数のあいだ使えるようになるのを待つ
action{ id = アクション ID, type = 1 }
targetselfself（自分）・target（今のターゲット）・entity（key にタイムラインの敵のキー）
satisfiedBy{ buffs = { 効果 ID } }：その効果がもう出ていれば使わない
onAction分岐のイベントで、来た技がこれ（数か配列）のときだけ
sound"x.wav"、または { file = "共通.wav", byAction = { [技 ID] = "y.wav" } }
executetruefalse ならドライランだけ
priority"weave""now" にすると、ほかの動きより先に使う
プランのファイル名を <ジョブ>_ANY.lua にすると、ポジションに関係なくそのジョブで使います。<ジョブ>_<ポジション>.lua があればそちらが先です。

共有するとき

  • 渡すのはタイムラインだけで大丈夫です。プランは人それぞれなので、受け取った人が自分で作ります。
  • 直したら meta.version を上げてください。プランが作られた版と違うと、アドオンが注意を出します。
  • 変換ツールが書き出したタイムラインの先頭のコメントには、使ったプル数や注意が書かれます。共有の前に、プレイの日時など残したくない情報が無いか確かめてください。
